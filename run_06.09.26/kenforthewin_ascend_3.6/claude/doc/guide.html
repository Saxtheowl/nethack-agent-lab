Comment Claude joue à NetHack, et comment tout le système tient debout

Ce guide raconte ce qu'on a construit depuis le 27 septembre : l'idée, qui joue, où tournent les choses, les styles de jeu essayés, ce qui tue nos Valkyries, ce qui marche, et comment un autre agent (Codex) peut venir jouer à côté.

1. Le défi

En septembre 2026, GPT 6 « Astra » a gagné une partie de NetHack 3.6.7 (une ascension) sur le serveur public Hardfought, en jouant touche par touche à travers un terminal, sans bot : environ 44 000 commandes sur 3 campagnes, une victoire sur trois. Le code de son harnais est public (kenforthewin/nethack_astra, licence MIT).

Notre défi : reproduire ça ici, « en pur », avec Claude à la place d'Astra, et pouvoir regarder les parties en direct depuis ce PC.

Les règles « PURE »
  • NetHack 3.6.7 vanilla, compilé depuis le tarball officiel. Aucun patch, aucun mode wizard/explore, aucun bot.
  • Jamais de save-scum : on ne copie ni ne restaure jamais une sauvegarde pour annuler une mort. Mort = partie finie.
  • Chaque décision est prise par l'IA après avoir lu l'écran. Les petits scripts ne font que des gestes bornés qui s'arrêtent au moindre danger.
  • Spoilers, wiki et code source de NetHack : autorisés (Astra les utilisait aussi).
Une seule exception, accordée par l'utilisateur : le déplacement unique, sans copie gardée, des sauvegardes de 3 parties du PC vers le worker (§6).

3. Qui joue : un orchestrateur et des agents

Il n'y a pas « un » Claude qui joue 8 parties. Il y a un orchestrateur (la session Claude Code avec laquelle tu parles) et un agent par partie : un sous-agent Claude (modèle Claude Opus 5.5), lancé par l'orchestrateur, qui joue une seule partie.

La vie d'un agent

  1. Il lit ses consignes : memory/session.md (règles, outils), memory/astra-style.md (le style et les leçons de toutes nos morts), puis son journal (memory/slotN-run-M.md).
  2. Il regarde l'écran (slots/N/v), décide, envoie des touches (slots/N/k), relit l'écran… des centaines de fois.
  3. Il commente ses décisions (say, visible en direct) et note les moments importants (chronicle).
  4. Il met à jour la ligne URGENT de son journal : tour, niveau, HP, armure, dernière prière, dangers.
  5. Quand son contexte devient lourd (après quelques heures), il s'arrête proprement sans arrêter la partie. L'orchestrateur relance un agent neuf qui repart du journal. Une partie peut ainsi passer par 5 ou 6 agents successifs.
  6. S'il meurt : section DEATH + leçons dans le journal, puis stop. L'orchestrateur décide de la suite.
La mémoire d'une partie, c'est son journal ; la mémoire collective, c'est memory/astra-style.md, où l'orchestrateur ajoute chaque leçon importante (zoo de Sokoban, Castle, fontaines…) pour que les agents suivants ne refassent pas l'erreur.

4. Comment un agent « voit » le jeu

NetHack tourne dans un terminal de 144 colonnes × 36 lignes (interface curses d'Astra). L'agent ne voit pas d'image : il lit le texte de l'écran. L'outil v le lui présente de façon compacte :

Terminal cursor (x,y; usually hero when no menu): 37,23      ← la position du héros
01 │You kill the jackal!                                       ← messages
...
34 │Dlvl:5  $:120  HP:43(52)  Pw:7(7)  AC:2  Xp:6/412  T:3120  ← statut
Map features (x,y): <@7,16 @@37,23 d@38,22 {@30,26 ...        ← chaque objet de la carte avec ses coordonnées
PETS (hilite, never attack): 38,22
Neighbors of @(37,23): 7:·(36,22) 8:·(37,22) 9:d(38,22) ...   ← les 8 cases autour du héros
OutilRôle
kenvoyer des touches (le pavé numérique sert aux déplacements)
t X Yse déplacer vers une case (commande travel)
look X Yidentifier un monstre / objet à distance
invinventaire complet (le panneau de droite est coupé après ~33 lignes)

wlancer un script écrit par l'agent lui-même, sur le worker

Les agents écrivent aussi leurs propres outils (solveurs de Sokoban, repos sur Elbereth, lancer de dagues…) dans slots/N/, comme Astra le faisait.

Beaucoup de morts venaient d'un agent qui laissait tourner une boucle sans regarder. Le harnais refuse donc maintenant certaines touches, pour tous les agents :

6. Ce qui tourne où : le PC et le worker

Depuis le 27/09 au soir, le PC ne fait plus tourner que Claude ; tout le reste vit sur le worker.

Pourquoi ? Le PC (4 cœurs) saturait : 8 agents, 8 parties, le recorder, le site, les outils. Tu as demandé que tout calcul hors Claude parte sur le worker (11 cœurs). On l'a fait en plusieurs étapes :

Calculs lourds → worker les solveurs de Sokoban passent par onworker ; un watchdog tue tout script local trop gourmand.
Site et recorder → worker le site est servi par le worker ; le PC ouvre juste un tunnel ssh pour garder l'adresse 127.0.0.1:8766.
Toute nouvelle partie démarre sur le worker les commandes des agents (slots/N/*) regardent .runtime/where-N et s'exécutent sur la bonne machine (scripts/slotrun).
Les 3 dernières parties du PC transférées sauvegarde, déplacement unique du fichier (exception accordée), reprise sur le worker.
Concrètement, quand un agent tape slots/3/k 6 sur le PC, la commande part par une connexion ssh ouverte en permanence, s'exécute sur le worker, envoie la touche à la tmux de la partie 3, et renvoie l'écran. L'agent ne voit pas la différence.

  • Tester les objets sur un altar (béni / maudit) avant de les porter.

  • La wand of wishing du Castle : la partie 3 y a pris gray dragon scale mail, shield of reflection et amulet of life saving.

10. Un 4e joueur : Codex

Un agent qui n'est pas Claude peut jouer sa propre partie à côté des nôtres, avec les mêmes outils, les mêmes garde-fous, et apparaître sur le site. Tout est expliqué dans doc/agent-externe.md. En bref :

scripts/external_slot.sh 4 Codex     # ouvre l'emplacement 4, partie au nom de « Codex » sur le worker
slots/4/v                            # Codex regarde son écran
slots/4/k 6                          # … et joue
slots/4/say "Je descends au Dlvl 2"  # ses commentaires apparaissent sur le dashboard

Sa carte apparaît sur le Dashboard avec le style « Codex (agent externe) », et ses statistiques rejoignent l'Historique pour comparer les deux IA.
