# BotHack × Jev — isolated experiment

This workspace adds three experimental policies next to the existing BotHack
3.6.7 project.  It does not modify or copy the baseline.  By default the
baseline is read from `../claude`; set `BOTHACK_BASE` or pass
`--bothack-base PATH` to use another checkout.

## Architecture found in the baseline

NetHack 3.6.7 is patched with a `bot` window port.  It sends typed JSON-line
requests (`cmd`, `yn`, `line`, `menu`, `pos`, etc.) and incremental map,
status and inventory observations.  `nhbot.engine.Engine` owns the process and
isolated game directory.  `pybothack.nhbridge.Bridge` renders those
observations into BotHack's world model and translates BotHack actions back to
typed protocol replies.  The `Delegator` asks ordered `choose_action(game)`
handlers for an action.  `nhbot.rungame`, `Recorder`, and `Supervisor` provide
reproducible seeds, verdicts, milestones, traces, limits and loop detection.

That `choose_action` boundary is the only strategic seam used here:

* `JEV_RAW` prevents `mainbot` from loading and offers Jev direct moves,
  search/wait/pray, stairs, doors, pickup, and explicit inventory actions.
  World parsing, prompt handling, protocol safety and logs remain BotHack's.
* `JEV_PRIMITIVES` prevents `mainbot` from loading and offers intentions such
  as fight, recover, collect, equip, explore, seek Mines, and go deeper.  The
  selected intention returns an action generated by BotHack's reliable world,
  inventory and pathfinding functions.
* `JEV_SHADOW` leaves BotHack intact.  It asks Jev only at goal changes,
  branch/inventory changes, major actions, detected local stagnation, and a
  250-turn heartbeat.  Jev's answer is logged and never executed.

The shared `OpenRouterDecider` is deliberately model-agnostic.  The policies
depend only on its `choose(state, choices, instructions)` interface.

## Run a first comparable experiment

Export an OpenRouter key, then use the same seeds and limits for all modes:

```bash
export OPENROUTER_API_KEY=...
python3 run_matrix.py --out runs/minetown-01 \
  --seeds 42001,42002,42003 --goal minetown --max-turns 30000
python3 compare_experiments.py runs/minetown-01
```

For a single variant:

```bash
python3 JEV_RAW/run.py --out runs/raw-42 --seed 42 --goal minetown
python3 JEV_PRIMITIVES/run.py --out runs/prim-42 --seed 42 --goal minetown
python3 JEV_SHADOW/run.py --out runs/shadow-42 --seed 42 --goal minetown
```

`--jev-offline` is only a plumbing smoke test: it always picks the first
candidate and must never be reported as a Jev result.  `--no-assist` applies
the same unassisted condition to any mode.

Each experimental game adds `jev_decisions.jsonl`.  A decision record contains
the visible state, candidate descriptions, selected option, full probability
distribution, confidence, execution flag, latency, usage and cost.  The next
record links the choice to its observed turn/position/HP delta and messages.
`manifest.json` stores the mode, model, endpoint, baseline path and experiment
code hash; `result.json` adds aggregate Jev calls, errors, tokens, cost, and
latency.  Existing BotHack evidence files remain unchanged.

## Experimental cautions

Jev is a typed decision model, not a text-generating planning agent.  Results
measure its ability to select among the candidate set exposed by each policy.
Candidate construction, assist settings, model id and code hashes therefore
belong in every comparison.  Start with Minetown and at least several fixed
seeds; only expand to Castle and later milestones after inspecting loops and
failure signatures.  Pin `typesafe/jev-1.13` for comparisons; test the moving
alias separately if desired.

No real Jev games were run while building this workspace because no
`OPENROUTER_API_KEY` was present.  Offline end-to-end smoke runs and the
baseline unit suite were run instead.
